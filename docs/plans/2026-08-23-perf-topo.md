# Perf plan — execution topology (2026-08-23)

Dependency topology for `2026-08-23-perf.md`. Nodes are the perf plan's
commits 2–5; edges are derived from actual file seams in the repo, not
from the plan's prose. The perf plan locks **sequential** execution
(§Method: "no fan-out — files overlap"); this document makes that lock
explicit and auditable.

Node C1 (the perf plan itself) is already on disk; it is the root of
every path and is not scheduled.

## Edges

Edge types: **dep** = semantic (later node needs the earlier one's
interfaces/gate), **conflict** = same-file overlap forcing merge order.

| Edge | Type | Shared seam / reason |
|---|---|---|
| C2 → C3 | conflict | both edit `complete()` in both providers — C2 adds `retries` passthrough, C3 adds `on_usage` param; same signature line |
| C2 → C4 | conflict | `builtin/config.py` DEFAULTS + `cli.py` flag block |
| C3 → C4 | dep + conflict | C4 rewrites `agent.run()`'s tool loop; C3 edits the same `run()` (usage buffering + emit) — C4 must build on C3's shape; also both touch `tests/test_agent.py` |
| C2 → C5, C3 → C5, C4 → C5 | dep | README documents each node's config keys, events (`usage`), commands (`/usage`), LOC totals — C5 is a pure sink |

**Non-edges**: none. Every executable node touches providers, `agent.py`,
`config.py`, or `cli.py`, which C2–C4 each occupy — there is no
parallel-safe wave in this DAG, so sequential execution is forced.

# Scout perf PR — retries, usage metering, parallel tools (2026-08-23)

Execution plan for the three performance/observability features agreed on
2026-08-23. Branch `perf`, one PR, one commit per phase, each commit leaves
`uv run pytest -q` and `uv run ruff check` green.

## Intent

Cut the two real costs in scout's wall clock and add the observability to
prove it:

1. **Retry with backoff** — one transient 429/5xx no longer kills a run
   (`scout/http.py` today raises on first failure).
2. **Usage events + meter** — per-turn token counts, including Anthropic
   cache hit/creation tokens, so the existing `cache_control` markup can be
   verified against reality. No cost estimates (decision: tokens only).
3. **Parallel tool execution** — the loop runs tool calls in a turn
   concurrently instead of serially (`scout/agent.py:42`); wall clock for
   multi-tool turns drops from sum(durations) to max(durations).

## Product decisions (locked 2026-08-23)

| Question | Decision |
|---|---|
| Parallel tool policy | All tools in parallel, `parallel_tools` config kill-switch |
| Usage display | Tokens only, no price tables |

## Method

Sequential commits, no fan-out (files overlap in `agent.py` / providers /
config). Never weaken a release gate. LOC budget ±20% of current
~1,470 → ceiling ~1,770; planned runtime delta ~+150 (→ ~1,620).

Constraints discovered in research that shape the design:

- `tests/test_kernel_purity.py` pins kernel→builtin imports to the three
  seams (`session`, `prompt`, `skills`). Neither feature here needs one:
  `concurrent.futures` is stdlib and the bus already carries arbitrary
  event types.
- `builtin/session.py`'s sqlite connection is `check_same_thread=True`
  (default). Parallel execution must keep **all bus emits on the main
  thread**; worker threads only run `registry.dispatch`.
- `tests/test_agent.py::test_loop_events` pins the exact event sequence.
  The serial path (single call per turn, or kill-switch on) must emit the
  identical sequence.

## Commit 2 — Retry with backoff (kernel: `scout/http.py`)

`post_sse()` becomes a thin wrapper that calls the current generator
(renamed `_post_sse_once`) up to `1 + retries` times:

- **Retry only pre-stream failures** — connection errors and bad HTTP
  status before the first SSE event has been yielded. Once the generator
  yields its first event, a later failure raises immediately (retrying
  would duplicate already-streamed text).
- **Retryable**: `urllib.error.HTTPError` with code in
  `{429, 500, 502, 503, 504, 529}` (529 = Anthropic overloaded) and
  `urllib.error.URLError`. Everything else (400/401/403/404/422) raises
  the existing `ScoutError` on first attempt.
- **Backoff**: `0.5 * 2^n + jitter`, capped at 8s; if the response carries
  `Retry-After` (int seconds), use it capped at 30s instead of the
  computed delay.
- New param `retries=2`. Config: `retries` added to
  `builtin/config.py` DEFAULTS, `--retries` CLI flag, `SCOUT_RETRIES` env
  (int coercion in `host.py` already handles it). Both providers pass
  `self.cfg["retries"]` through to `post_sse`.

**Tests** (`tests/test_http.py`, new; monkeypatch
`urllib.request.urlopen` and `time.sleep`, no network):

- 429-then-success succeeds; sleep called with backoff schedule.
- `Retry-After: 3` honored over computed delay.
- 400 raises immediately, exactly one attempt, body surfaced.
- Exhaustion raises `ScoutError` carrying the last error body.
- First event yielded, then connection dies → not retried.

## Commit 3 — Usage events + meter

**Client protocol change** (breaking for third-party provider plugins —
acceptable, flagged in the PR description and README):

```
complete(system, messages, tools, on_text=None, on_usage=None)
```

Providers call `on_usage(dict)` once at stream end.

- `builtin/providers/anthropic.py`: capture `message_start` →
  `message.usage`, merge `message_delta` → `usage` (final output token
  count). Normalized fields: `input_tokens`, `output_tokens`,
  `cache_read_input_tokens`, `cache_creation_input_tokens` (missing keys
  default 0). This is what verifies the cache markup actually hits.
- `builtin/providers/openai.py`: add
  `"stream_options": {"include_usage": true}` to the payload; read the
  final chunk's `usage` (`prompt_tokens`, `completion_tokens`,
  `prompt_tokens_details.cached_tokens` → mapped into the same normalized
  shape). Risk: an exotic compat server that rejects `stream_options` —
  accepted, revisit if reported.
- `scout/agent.py`: buffer the callback; `bus.emit("usage", model=..., **counts)`
  immediately **after** `message.assistant` (natural log order; the
  projector ignores unknown event types).
- `builtin/usage.py` (new, ~45 LOC): subscribes to `usage`; prints one
  line per turn (per-turn delta + running session total) to the display
  stream — reuse `display._stream()` so `-p` mode flips it to stderr.
  Registers `/usage` (session totals). Added to MANIFEST between
  `display` and `commands`.

**Tests**: anthropic fixtures gain `message_start`/`message_delta` usage
payloads (incl. cache fields); openai payload asserts `stream_options`;
agent emits `usage` after `message.assistant` with normalized fields;
meter output respects `display.stderr`; `/usage` totals. `FakeClient`
signatures updated in `test_agent.py` / `test_host.py`.

## Commit 4 — Parallel tool execution (kernel: `scout/agent.py`)

When `len(calls) > 1` and `config["parallel_tools"]`:

```
emit tool.start for all calls      (call order, main thread)
submit registry.dispatch(...) to ThreadPoolExecutor(max_workers=min(n, 8))
as futures complete → emit tool.end (completion order, main thread)
assemble results by index          (API sees call order, always)
```

- **All bus emits stay on the main thread**; workers only run
  `registry.dispatch` (see sqlite constraint above). Tool audit: bash
  (subprocess), read/grep/glob/skill (pure reads) — thread-safe;
  write/edit — concurrent same-file writes possible, accepted as a model
  error (matches Claude Code semantics).
- Kill-switch: `parallel_tools: true` config default;
  `--no-parallel-tools` CLI flag; `SCOUT_PARALLEL_TOOLS` env. The env
  loop in `host.py` currently coerces only ints — add bool coercion
  (`true/false/1/0`, else `ScoutError`).
- Ctrl-C: on `BaseException`, `executor.shutdown(wait=False,
  cancel_futures=True)` and re-raise. Known limitation: an in-flight bash
  process runs to its timeout.
- Single-call turns and `parallel_tools=false` keep the exact current
  serial path — the pinned event sequence in `test_loop_events` is
  untouched.

**Tests**: two staggered-sleep tools (0.5s each) → results array in call
order, `tool.end` events in completion order, wall clock < 0.9s; kill
switch runs serial (wall clock ≥ sum); error results unaffected;
`test_loop_events` still green unchanged.
